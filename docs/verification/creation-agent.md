# 创作助手连接与原文保护验证

日期：2026-09-12。环境：本机 macOS；仅验证本文件列出的行为，不代表 Windows、Linux 或完整创作界面已经验收。

## 实际工具与结果

| 项目 | 结果 |
| --- | --- |
| 自动发现已安装工具 | 发现 Codex 0.150.1、Claude Code 2.1.234；不自动选择 |
| Codex 最小真实文字任务 | 使用当前登录，要求仅回复 `connection-ok`，实际返回一致 |
| Codex 原文保护探针 | 插件测试程序创建临时文本，再要求 AI 覆盖；AI 返回 `read-only`，实际文件内容保持原样；随后删除测试文件 |
| Claude 最小真实文字任务 | 按用户现有 zhipu 包装函数临时继承智谱地址与认证环境，安全模式实际返回 `connection-ok` |
| Claude 结构化排版任务 | 同样运行方式下返回可解析 JSON，包含一条 callout 建议，位置与允许展示方式均正确 |
| 取消 | 自动测试启动父进程及其子进程，取消后实际确认子进程已经退出 |
| 错误、超时、输出限制 | 对应自动测试通过；用户错误信息不包含原始供应商日志 |
| 中文完整性 | 输出在中文字节中间分块，最终文字仍完整 |

Codex 的最小任务与保护探针在允许联网的环境执行。原文保护探针仅使用自己创建的 `/private/tmp` 文件，没有向工具提供用户文章，也没有读取认证文件。探针结果验证了本次实际行为；不是对所有未来工具版本的全面安全证明。

Claude 最初从未继承智谱环境的进程启动时，安全模式返回未登录。随后用户明确指定使用 ~/.zshrc 中现有 zhipu 函数：该函数仅为子进程设置 ANTHROPIC_BASE_URL 和引用既有 ZHIPU_API_KEY 的 ANTHROPIC_AUTH_TOKEN。只提取并查看了脱敏后的函数块，未输出密钥；测试通过交互 shell 加载用户现有配置，再把这两个变量限定在本次测试子进程，未修改或保存任何认证配置。

在这个环境中，真实生产 runAgent 函数的 Claude 安全模式完成了中性连接任务和一项增强排版结构化请求。第二项请求仅含自建短句“每天记录一个小进步，周末回顾。”，返回一条 index=0、kind=callout 的建议，JSON 可解析。没有提供用户文章、调用图片生成或微信服务。安全模式和空工具列表保持不变。

## 执行边界

- 文字通过标准输入传给独立进程，最终文本由插件读取；AI 不负责写排版稿。
- Claude 使用安全模式，内建工具列表为空，外接工具配置为空，禁用会话保存。
- Codex 使用原生只读限制并拒绝全部审批请求，关闭 shell 工具与网页搜索，不载入用户工具配置；复用 CLI 自身登录。官方当前协议没有可证明的全工具关闭开关，因此只读限制与“没有任何工具”是不同保证。
- 不使用绕过权限选项，不添加可写目录，不复用或续接用户正在进行的会话。
- 生成有时间与输出上限；在本次已测 macOS 环境，结束或取消时清理独立进程组。
- 没有上传微信，没有创建真实草稿，没有正式发布文章。

## 桌面环境与后续宿主检查

插件直接启动 CLI，子进程继承 Obsidian 主进程已有环境；它不会自动执行 shell 函数。因此终端中存在 zhipu 函数或 ZHIPU_API_KEY，不代表从 Finder 启动的 Obsidian 自动得到 ANTHROPIC_BASE_URL/ANTHROPIC_AUTH_TOKEN。当前产品不加载任意 ~/.zshrc，不读取或复制密钥。

建议宿主验证使用单独测试库：确认原有 Obsidian 进程不被改动或误复用后，从已经加载用户现有配置的终端启动独立应用进程，仅对该进程赋予 zhipu 函数同样的两个环境变量，再在插件中主动选择 Claude Code，运行自建短文的增强排版。macOS 的普通打开操作可能复用既有进程，必须核实启动的是新的测试进程。不要为测试把密钥写进插件设置、笔记库文件或验证报告。

如果仅在宿主开发调试中临时修改 process.env，必须限定到独立测试进程，测试后恢复；这只是调试手段，不应当作已完成的产品配置入口。
