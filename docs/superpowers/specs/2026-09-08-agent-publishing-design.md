# Obsidian 通用 Agent 排版发布体验设计

日期：2026-09-08（CLI 必要性复核后修订）  
状态：方案制定完成；尚未实施、尚未通过体验验收。  
边界：本轮不改动 md2wechat CLI 仓库；使用已核对的 3.5.0 公开命令。此前拟议的 stdin、review-bundle 和 reviewed publish 扩展已撤回。  
依据：本次 geekx-gate 审查，以及用户明确要求“当前文章 → Agent 排版 → 插件展示结果 → 确认创建草稿”，支持不同 Agent 共存。

## 1. 产品决定

本次升级只做好一件事：让用户在常用 Agent 中提出排版要求，在 Obsidian 中审阅成品，然后确认创建一个公众号草稿。

- Agent 负责理解文章、判断是否需要模块、选择主题、组织排版；复用 md2wechat 的共享 skill。
- md2wechat CLI 负责发现、结构校验、转换、素材处理和草稿创建；不加入主观文风评分或词表决策。
- Obsidian 插件负责当前编辑内容、成品展示、少量调整、恢复和最后确认。
- 插件不直接调用转换服务或公众号 HTTP 接口，不增加模型设置或聊天窗口。
- 不假设用户只安装了一个 Agent。Claude Code、Codex、Claudian、WorkBuddy、ZCode 使用相同接力约定，互不抢占。

这里的“通用”是同一台电脑、同一用户下，宿主能执行本地命令并读取获准的工作文件。纯云端、无本地执行能力的聊天产品不在本轮支持范围。产品名出现在兼容表中，不等于已经实测通过。

## 2. 为什么不能直接交付旧分支

### 已核对的基线

| 对象 | 本次读取的基线 | 处理方式 |
|---|---|---|
| 插件 main | `a13bec2`，1.0.3 | 新开发分支从执行时核对过的 main 建立 |
| 插件旧开发分支 | `codex/workbench-v2`，`05fdd8b` | 作为已实现能力的供体，按文件和行为选择性复用 |
| CLI 当前 main | `cbc8c600`，3.5.0 | 只读依赖，不修改代码、skill 或版本 |
| CLI 旧开发分支 | `codex/obsidian-stdin-contract`，`c0f834f5` | 不迁移，本轮不依赖其中的新能力 |
| 本机 Obsidian 安装器 | 1.8.10 | 不修改现用安装；先隔离验证新基线 |

执行时必须再次核对以上引用，不能把本表当成永远不变的 HEAD。CLI 历史遍历曾出现缺失对象，开始复用前检查所需树与文件完整性；不能因此重置用户分支或修写共享历史。

### 已确认的产品问题

1. 旧工作台要求用户建立会话、选择模块、填写表单，缺少 Agent 成品接力。
2. 改原文后会话失效，重建会丢掉新增模块；关闭工作台也未接通放弃修改确认。
3. 中间 Markdown 优先于预览展示，旧版带格式复制没有保留。
4. 模块数被固定为 53；当前 CLI 的 56 个模块使整个工作台被阻断。
5. 当前正式 CLI 缺少旧分支声明的 stdin/source-path 能力，不能靠“版本大于 3.3.0”判断可用。

旧分支的测试不能自动作为本设计的验收证据。新行为必须重新验证。

## 3. 接入路线与取舍

### 采用：Agent 发起 + Obsidian 官方命令行 + md2wechat

Obsidian 已提供 `registerCliHandler`，官方类型注明自 1.12.2 提供；官方 CLI 安装说明要求更新安装器，推荐 1.12.7 或更高。拟定新插件基线：**Obsidian 桌面端 1.12.7+，安装器 1.12.7+，官方 CLI 已启用**。最低应用和安装器都要实测，不只改 manifest。

插件仅注册两个窄命令：

```text
md2wechat-publisher:capture   取得指定笔记的当前编辑内容，返回本次工作文件位置
md2wechat-publisher:present   接收已完成的排版包，在正确的笔记／窗口中展示
```

宿主执行官方 `obsidian` 命令取得上下文，使用 `md2wechat` 完成排版，再调用 present。插件的接力 skill 随插件分发，调用现有 md2wechat skill 和命令，不修改 CLI 仓库。两项操作均不能上传、创建草稿、写回笔记或运行任意传入命令。

首个实施任务必须证明：最低基线上的命令返回、异步文件写入返回、中文路径、弹出窗口、两个 Vault 和两个 Agent 并发均正确。没有通过，不固化接入层，不宣称原生接力已完成。

### 不采用的路线

| 路线 | 不采用原因 |
|---|---|
| 分别调用 Claudian／Codex／WorkBuddy／ZCode 的内部对象 | 升级易断、需要维护多份逻辑，且会擅自决定用户用哪个 Agent |
| 为旧 Obsidian 自建 HTTP 服务、轮询队列或常驻桥接程序 | 增加安装、端口、运行状态和维护负担；本轮不为 1.8.10 保留第二套实现 |
| 插件内直接启动模型或嵌入聊天 | 重复用户已有 Agent，偏离主流程 |

升级 Obsidian 是本方案明确代价。当前规划不执行升级，也不替换现用插件。若官方入口在隔离验证中失败，先解决或调整最低基线，不能悄悄换成私有接口、键盘注入或复制粘贴并宣称等价。

## 4. 用户实际怎样使用

### 4.1 正常主流程

1. 用户在任意已配置的本地 Agent 中说：“把 Obsidian 当前文章排版成公众号文章，给我预览。”
2. Agent 获取当前编辑内容，选择必要主题与模块，完成校验和预览；插件自动展示结果。
3. 用户检查预览，点击“创建草稿”，在一个原生确认窗口内核对账号、封面和文章资料，点击“确认创建”。

配置完成且资料齐全时，用户主动触发动作共三个：发出排版要求、打开草稿确认、最终确认。正常流程不要求复制正文、执行命令、选择结果文件、逐个挑模块或点击“建立会话”。观察预览不计为一次按钮操作，首次配置单独计时，不能偷换统计范围。

### 4.2 从插件打开

插件图标与命令“打开公众号预览”用于查看当前文章已有结果。没有结果时显示一句示例请求和“接入我的 Agent”帮助入口。**不摆放一个无法可靠分派宿主的“一键 AI 排版”按钮。**初次接入可选择多个宿主查看对应安装说明；这只改变帮助内容，不建立默认宿主、不读取宿主密钥。

未使用 Agent 的用户仍可点次要操作“直接预览原文”，使用同一个 CLI 完成普通排版；明确不宣称这是 Agent 优化结果。

### 4.3 调整

- 常用调整仅保留主题、字号、文章资料；调整后在后台生成新候选，成功前保留旧预览。
- 主题使用 CLI 实际默认值、该文章上次选择，再考虑 Agent 的明确选择；不可随意取列表第一项。
- 初始主题选择展示当前主题和最近使用项，全部主题可搜索；不启动即渲染几十张主题缩略图。
- 修改文案、模块或排版策略仍在原 Agent 中继续描述；共享 skill 可读取该文章最近的成品作为修改参考。
- 带格式复制为常驻次要操作；原始 Markdown／HTML 导出放在更多菜单。
- 本轮不做模块目录、九类动态表单、光标插入编辑器或自建聊天。

## 5. Obsidian 原生设计规范

设计方向：安静、精确、预览优先。精致感来自文章比例、对齐、留白、真实反馈和一致操作，而非额外装饰。

### 5.1 页面结构

```text
┌ 当前文章标题（单行省略）                 更多 ┐
│ 已更新 · 主题名称                         │
│                                          │
│              文章真实预览                 │
│      标题、正文、图片和模块占据主空间       │
│                                          │
├ 主题 ▾    字号 ▾         文章资料          ┤
│ 复制到公众号                  创建草稿     │
└──────────────────────────────────────────┘
```

- 桌面右侧单一可停靠视图；用户可移至主区域或弹出窗口，插件尊重位置，不反复抢焦点。
- 标题栏最多两行；没有问题时不显示诊断入口、检查长表和技术状态码。
- 有结果的 900px 高测试窗口，预览区域至少占可用内容高度 65%；空态不显示大面积禁用按钮。
- 正常状态只有“创建草稿”一个强调按钮。主题、字号、复制为次要控件。
- 窄面板 320／360／420px，无横向页面滚动；底部操作可自然换行且不遮挡正文。640／900px 宽时预览居中，不拉成长行。
- 文章预览以约 375 CSS px 的公众号阅读宽度为基准，宽屏居中；窄屏使用真实可用宽度。它是阅读参考，不宣称与每款微信设备逐像素一致。
- 外层界面继承 Obsidian 主题；文章本身保持输出主题，不能因 Obsidian 深色模式擅自反转将要发布的文章颜色。

### 5.2 控件与外观

- 使用 Obsidian `ItemView`、`Modal`、`Setting`、`Menu`、`setIcon`，不重造对话框、菜单和图标体系。
- 使用宿主的界面字体、字号、背景、文字、边框、强调色、圆角和间距变量；所有样式限定在插件前缀下。
- 4px 节奏参考，优先使用宿主现有 spacing 变量。界面不能强制远程字体、品牌紫渐变、玻璃效果、大阴影、卡片套卡片。
- 普通正文／说明文字对比度至少 4.5:1；大字／必要图形至少 3:1，作为本项目验收阈值。颜色不作为唯一状态提示。
- 图标操作有中文名称和悬停说明；点击区域至少 28×28 CSS px，主要操作至少使用宿主标准控件高度。
- 键盘可完成主题选择、复制、确认与取消。焦点清晰，Esc 关闭对话框，关闭后回到触发控件；不抢注默认快捷键。
- 输入文章资料时不重建整个面板，不丢焦点、光标、输入法组合或滚动位置。
- 动效仅用于进度与状态转换，120–180ms，尊重减少动态效果设置；不模拟百分比、没有装饰性进场动画。

### 5.3 必须设计并实测的状态

| 状态 | 用户看到什么 | 下一步 |
|---|---|---|
| 没有文章 | “打开一篇 Markdown 笔记后开始” | 不展示无意义表单 |
| 没有成品 | 一句跨 Agent 示例与接入帮助 | 直接预览原文仍可用 |
| 正在排版 | 真实阶段：“正在准备文章／生成预览” | 能停止接收这次结果；不假装能停止外部 Agent |
| 可预览 | 文章成品及简短更新时间 | 调整、复制、创建草稿 |
| 原文已改 | “原文有更新，当前显示上次排版” | 旧成品完整保留；需要新排版才能创建新草稿 |
| 新预览失败 | 保留上次成品，说明本次失败和可执行修复动作 | 不把旧成品标为本次成功 |
| 图片缺失 | 指出对应图片及所在段落 | 查看／替换图片，不只显示错误码 |
| 发布检查缺项 | 在确认窗口内定位缺失的账号／封面／资料 | 补齐后原窗口继续，不重复确认 |
| 正在创建 | “正在创建草稿，请稍候” | 禁止重复提交；关闭面板不代表撤回 |
| 创建成功 | 账号、标题、时间，返回的链接或公众号后台入口 | 不显示“已发布” |
| 结果不确定 | “暂时无法确认是否创建成功，请到公众号后台核对” | 保留核对信息；无自动重试按钮 |

“停止接收”只让当前 request 不再自动替换可见成品。外部 Agent 后续交付仍可保留为未采用结果；插件不声称已经取消宿主任务。

## 6. 最小跨工具约定

### 6.1 工作文件与命令

capture 由插件读取真实 Editor 缓冲区，而非 Agent 重读磁盘。将正文副本和本次需要的图片保存到插件管理的工作目录；原笔记、原附件不修改。已有笔记的未保存修改必须包含；完全没有资源基准的笔记提示先保存一次。

```text
obsidian vault=<vault-name-or-id> md2wechat-publisher:capture [source=<vault-relative-note>]
  → JSON: schemaVersion, requestId, vaultPath, sourcePath, sourceHash,
          inputFile, workDir, previousResult?

md2wechat inspect <workDir>/formatted.md --json
md2wechat preview <workDir>/formatted.md --theme <theme>
  --output <workDir>/preview.html --json
  → 使用当前已有 envelope、data.output_file、data.inspect 和 data.render

obsidian vault=<same-vault> md2wechat-publisher:present
  request=<requestId> markdown=<workDir>/formatted.md
  preview=<workDir>/preview.html response=<workDir>/preview-response.json
  → JSON: schemaVersion, requestId, state=presented|source_changed|superseded
```

只有两个 Obsidian 插件命令是新建项；md2wechat 命令和参数均使用现有版本。preview-response.json 保存本次真实 stdout，不能手写成功输出。插件核对返回状态、output_file、实际文件、inspect 上下文以及 capture 关联后，自行创建本地成品记录；它不是 CLI 的新协议。

原生命令不等待远端转换。排版与转换由 Agent/CLI 独立完成，主流程无额外 HTTP 服务、守护程序或宿主适配框架。

### 6.2 临时正文与资源基准

当前 CLI 没有 stdin/source-path 扩展，因此以插件提供的临时文件为输入。原文身份由插件持有，CLI 仅处理合法普通文件。

- capture 用 Obsidian 的文件／嵌入引用信息与成熟 Markdown token 解析定位图片，复制实际引用资源到工作目录，用安全、无空格的文件名替换副本中的目标地址；正文、替代文字和原文件不变。
- 不能全局字符串替换、重写代码块中的示例或自己实现完整 Markdown／模块解析器。Obsidian wiki 嵌入转换属于插件与笔记格式的适配职责。
- 默认只使用原文已有素材，Agent 复用 inputFile 中已经归一的地址。未经请求不新增外部素材、不生成图片。
- 相对路径、中文空格、百分号编码、引用式图片、同名附件、Vault 嵌入必须进入测试。嵌入整篇笔记、视频等 CLI 不支持的内容明确提示，不谎称完整支持。
- 现有 CLI inspect 验证副本的最终图片是否存在；发现缺失先修正副本，不把“检查成功”当作“图片全部存在”。
- 远程图片作为明确引用的输入文件，使用受限文件下载固定到本地，遵循现有项目的地址和大小限制。这里仅获取文章素材，不直接调用转换／公众号 API，不上传。
- 若真实样本证明以上适配必须复制 CLI 大片解析或素材规则，停止扩展插件适配，提交具体失败样本，重新审查最小 CLI 改动；现在不预先升级。

### 6.3 插件本地成品记录

```ts
type Capture = {
  schemaVersion: 1; requestId: string; vaultPath: string;
  sourcePath: string; sourceHash: string;
  inputFile: string; workDir: string; previousResult?: string;
};
type ResultRecord = {
  schemaVersion: 1; requestId: string; sourcePath: string; sourceHash: string;
  markdownFile: string; markdownHash: string;
  htmlFile: string; htmlHash: string;
  previewResponseFile: string;
  assetBindings: Array<{ source: string; localFile: string; sha256: string }>;
  state: 'current' | 'source_changed' | 'superseded';
};
```

- 成品记录由插件写入，CLI 无需识别。原始 inspect/readiness 保留在 preview response，不再构造一份平台状态。
- 每次请求独立目录；插件复制候选到不可变成品目录后才切换 current。相同 request 与文件摘要重复 present 必须幂等。
- sourceHash 来自 capture 中真实编辑内容；外部 Agent 不能自行声明当前原文未变化。
- present 核对 request 所属 Vault、允许目录、文件类型、大小和摘要；拒绝目录逃逸、符号链接逃逸、残缺文件及错误版本。
- 内容不进入命令参数、日志、URI 或设置项。工作目录的访问由宿主正常授权，不自动放宽权限。
- 初始限额：Markdown 10 MiB、HTML 20 MiB、单素材 20 MiB、单结果 200 MiB，与当前 CLI 更严格限制取交集。
- HTML 放入禁脚本隔离预览。显示副本才映射 Obsidian 本地资源地址；导出和草稿使用原始已审阅 HTML。

### 6.4 Agent 工作约定

插件仓库分发一个 `skills/obsidian-md2wechat/SKILL.md`，只补捕获／返回约定，并复用现有 md2wechat 排版 skill；不复制主题、模块定义或每个宿主的整套 SOP。

1. 明确目标 Vault／文章，调用 capture，读取 inputFile；不覆盖原笔记。
2. 只进行当前任务所需 discovery，选择必要模块；必要字段不能诚实填写时不用模块。
3. 默认只排版、不改事实与正文含义；数字、引用、链接保留，资料建议仍是候选。
4. 写完整 formatted.md；通过 layout validate、inspect 和现有 preview；预览不是上传授权。
5. 只在本次 preview 确认成功后 present；失败不沿用旧输出路径。
6. Agent 到结果已展示结束，不执行 upload_image、download_and_upload 或 create_draft。

同一用户可同时从不同 Agent 提交请求。较旧请求晚到不覆盖较新结果，未采用结果可从“其他排版结果”恢复；不做 Agent 调度器。

## 7. 成品保存、改稿与恢复

- 成品保存在本机用户数据目录的 md2wechat 专用子目录，按 Vault 和文章隔离，正文目录不增加派生笔记，不默认同步到云端。
- 每篇文章保留当前和前一份已采用成品；尚未采用的工作、当前进行中的请求、结果不确定的创建记录不参与自动淘汰。
- 自动清理仅可删除更早、已经被后续成功成品替代的本插件结果；达到占用阈值提供“管理本地结果”，不静默清除未完成工作。
- 关闭面板／停用／重启后能恢复当前与前一份成品、选择的主题字号、资料修改和创建记录；持久化在确认显示成功之前完成，关闭不触发隐式发布。
- 原文改变：保留旧成品和当前选择，标为旧版本，阻止误创建草稿；不强行合并模块位置。新请求获取新原文，Agent 可读取 previousResult；新结果验证成功后才切换。
- 源笔记改名：通过 Vault rename 事件更新文章索引，不用相同文件名猜；删除源笔记后仍能看旧成品，但不能继续创建草稿。
- 断电／写入失败只损坏当前候选，不影响最后成功版本。旧结果损坏时明确说明，不显示空白成功页面。

## 8. 预览与创建草稿一致

**创建草稿消费已审阅的结果包，不重新调用转换服务排版。** 允许的变化仅是素材上传后替换为公众号地址，以及用户在最终确认窗口中明确修改的文章资料。

现有 CLI 已提供三个足够的公开动作：普通预览、图片上传、从 JSON 创建草稿。插件只编排这些动作，不复制上传、压缩、认证和公众号通信逻辑。

```text
# 最终确认以后，按冻结素材逐项调用（不经过 shell 字符串拼接）
md2wechat upload_image <frozen-image> --wechat-account <account> --json
# 使用返回的 wechat_url 替换已审阅 HTML 中与该素材绑定的图片地址
# 使用封面上传返回的 media_id 填入 thumb_media_id
md2wechat create_draft <plugin-owned-draft.json> --wechat-account <account> --json
```

草稿 JSON 使用当前已有 articles 数组及 title、author、digest、content、thumb_media_id 字段。content 为已审阅 HTML 的副本，只替换明确绑定的图片地址；不得再次调用 convert --draft，也不得将宿主显示资源地址交给公众号。

对应直接账号时省略命名账号参数；每个上传和创建动作前验证同一账号身份。插件检查 metadata 限制仍来自当前 inspect，不复制平台校验常量。

确认窗口只一层：账号、封面缩略图、标题、作者、摘要和“确认创建”。单账号自动选中；多账号使用该文章上次明确使用且仍存在的账号，否则选择一次；最终确认始终清晰展示目标。文章已明确提供封面时先验证并显示，不要求重复挑选。

- 平台限制和 readiness 来自 CLI inspect；缺少草稿账号不能阻断只读预览。
- 封面、结果文件或文章资料在确认后变化，确认失效，在原窗口提示更新；不发送旧确认对应以外的内容。
- 第一个外部副作用前持久化 attempt.started；成功写入完成记录；进程退出／超时／不可判定结果保留 unknown。插件的持久化记录与跨窗口锁对同一结果与账号重复尝试默认拒绝，防护跨面板、窗口和重启有效。
- 同一授权尝试最多一次草稿创建请求，不自动重试。素材已上传但草稿未确认成功时保留阶段信息，不谎称“没有任何变化”。
- 不确定结果只提供后台核对入口及标题／时间／账号；后续再次创建需要用户明确的新决定，不能因换窗口或重启绕过。
- 只有 CLI 返回有效草稿标识才显示成功。没有有效直达链接时只提供公众号后台入口，不编造草稿 URL。
- 预览和带格式复制不触发上传。复制遇到只能在本机显示的图片时，清楚提示图片需要补传；不以纯文本降级冒充带格式复制成功。

## 9. 复用与删除清单

| 内容 | 决定 |
|---|---|
| CLI 安全调用、结束清理、图片定位 | 复用并按当前 main 重测；编辑内容通过插件副本接入 |
| 当前 main 的 inspect/readiness、主题默认、素材与草稿链路 | 保留权威性 |
| 旧插件的版本检测、账号摘要、预览隔离与确认保护 | 选择性复用；改用普通文件输入，去除整台阻断和固定数量 |
| main 的带格式复制交互 | 保留用户能力，重写不安全或过时实现 |
| 53 模块选择、九类表单、offset 插入、会话撤销栈 | 不进入新分支，不先全部搬过来再维护 |
| 派生 Markdown 常驻、诊断大面板、建立／重建按钮 | 删除主流程入口 |
| 模型路由、Agent 自动选择、新 MCP／HTTP 服务 | 不做 |

旧设置迁移不自动把旧密钥转移到 CLI，也不在 CLI 未就绪时先清空旧版配置。新增设置只包括非敏感偏好与工具定位；原数据的清理是完成迁移后的明确操作，旧版回退路径要实际测试。

## 11. CLI 必要性裁决

**裁决：当前不升级 CLI。** stdin 是减少临时文件的便利，不是完成当前编辑内容排版的必要条件；review-bundle 是统一产物格式的便利，不是保存和恢复成品的必要条件；新增已审阅发布入口也不是必要条件，现有 create_draft 已接受排版内容。

本轮升级只有在以下证据出现时重新讨论：现有命令确实无法表达必要动作；真实素材在合法最小适配后仍失败；或两个以上客户端出现重复的大段平台业务逻辑。需要失败样本、最小改动和兼容测试，不能用未来扩展作为理由。

验证证据：当前 3.5.0 帮助与源码具备 preview、upload_image、create_draft 和命名账号参数；现有预览原样输出／失败不覆盖与草稿内容保留测试已通过；临时正文及规范化图片输入在当前 inspect 上验证通过，原文件未变。百分号编码路径的首次样本被当前 CLI 判为不存在，说明插件必须正确处理资源适配，不能只搬正文。真实图片上传和公众号草稿未执行，不宣称整条链路已验收。
